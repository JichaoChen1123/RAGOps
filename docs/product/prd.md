## 2. 背景与问题

RAG 应用效果下降时，团队通常只能看到最终回答，难以区分问题来自检索、排序、上下文、生成、引用还是评测器。Prompt、模型、Embedding 或 Rerank 版本变化后，也缺少可复现的同集对比，发布决策依赖零散人工抽查。

RAGOps 要把“准备测试集—运行评测—查看指标—定位失败—比较版本”收敛为一个可追溯的离线工作流。平台首先解决三件事：

1. 用同一数据集和同一评测口径复现结果。
2. 把总体分数下钻到失败样本和可核对证据。
3. 用成对版本对比回答“改动是否变好、变坏在哪里、是否可以发布”。

## 3. 目标与成功标准

### 3.1 产品目标

- 让 AI 应用开发者在 30 分钟内完成首次数据导入并获得可下钻的评测报告。
- 让 RAG 维护者能按检索与生成阶段定位疑似根因，而不是只得到一个总分。
- 让发布负责人基于同数据集、同指标配置的版本差异做发布判断。
- 保证每个报告都能追溯到不可变的数据集版本、应用配置快照、指标配置和执行记录。

### 3.2 MVP 成功指标

| 指标 | 口径 | MVP 目标 |
| --- | --- | --- |
| 首次价值时间 | 新用户从创建项目到首份成功报告 | 中位数不超过 30 分钟 |
| 报告可追溯率 | 可完整回溯四类版本信息的已完成报告占比 | 100% |
| 失败证据覆盖率 | 失败样本中至少展示一项可核对证据的占比 | 不低于 95% |
| 对比可解释率 | 版本对比中可下钻到样本级变化的指标占比 | 100% |
| 任务成功率 | 排除目标应用不可用后的评测任务成功比例 | 不低于 99% |

“诊断正确率”不在没有人工标注基线时承诺；MVP 必须把诊断表达为“疑似原因 + 证据 + 置信度/不可判定”，并支持用户反馈。

## 4. 目标用户与核心场景

| 用户 | 主要任务 | 当前痛点 | 期望输出 |
| --- | --- | --- | --- |
| AI 应用开发者 | 调试 Prompt、模型与链路参数 | 改动效果靠抽查，问题阶段不明 | 失败样本、阶段指标、前后版本差异 |
| RAG 系统维护者 | 优化召回、Rerank 和索引 | 只看到答案差，缺少检索证据 | Recall、排名、上下文覆盖与疑似根因 |
| 企业知识库负责人 | 维护评测集和知识覆盖 | 测试集格式不一、版本不可追踪 | 可复用数据集、字段质量和覆盖分布 |
| 模型应用后端工程师 | 保障接口稳定、成本与时延 | 效果与工程指标分散 | 错误、时延、Token/成本和失败请求详情 |
| 发布负责人 | 判断新版本能否上线 | 总均分掩盖回退样本 | 同集对比、回退清单和门禁结论 |

核心场景：

- RAG 问答效果变差，快速判断是检索未召回、排序靠后、上下文不足，还是生成幻觉。
- 检查回答是否引用来源，引用是否支持对应结论。
- Prompt 或模型升级后，与基线运行进行同集、同口径比较。
- Embedding、Rerank 或 Top K 改动后，评估召回、排名和最终回答的联动变化。
- 按业务标签筛选长尾失败，如产品线、语言、问题类型和知识域。

## 5. 产品原则与关键对象

### 5.1 产品原则

- **先证据后结论**：诊断必须展示触发指标和样本证据；证据不足时明确显示不可判定。
- **版本不可覆盖**：导入、配置或评测规则变化均生成新版本，历史报告不随当前配置变化。
- **同口径才对比**：默认只允许同一数据集版本与指标配置进行正式对比；不一致时阻止门禁结论。
- **总体可下钻**：每个聚合指标都能追溯到样本明细、原始输入和评测解释。
- **自动评测可复核**：模型评审结果必须保留评分理由、评审器版本和规则版本。

### 5.2 核心对象

| 对象 | 说明 | 最小追溯字段 |
| --- | --- | --- |
| 项目 | 一套 RAG 应用及其评测资产边界 | 名称、负责人、创建时间 |
| 数据集版本 | 一批不可变评测样本 | 版本 ID、文件摘要、样本数、字段映射、创建人 |
| 应用配置快照 | 一次运行所使用的 Prompt、模型、检索与 Rerank 配置 | 快照 ID、配置项、目标环境、密钥引用 |
| 指标配置 | 指标集合、阈值、评审规则和评审器版本 | 配置 ID、指标参数、规则版本 |
| 评测任务 | 用户定义的一次执行请求 | 数据集版本、应用快照、指标配置、创建人 |
| 运行 | 一次实际执行及重试记录 | 运行 ID、状态、时间、样本结果、错误 |
| 报告 | 运行结果的聚合与下钻视图 | 指标、分布、失败分类、样本证据 |
| 对比 | 基线运行与候选运行的成对差异 | 两个运行 ID、兼容性检查、差值、回退样本 |

## 6. MVP 范围

### 6.1 P0：必须交付

1. **项目与版本化配置**
   - 创建项目。
   - 登记应用调用目标和应用配置快照。
   - 记录 Prompt、生成模型、Embedding、Rerank、Top K、知识库/索引版本等可选字段；未上报字段显示“未知”，不得猜测。

2. **数据集导入与版本管理**
   - 支持 UTF-8 CSV 和 JSONL。
   - 字段映射、前 20 条预览、整批校验、错误下载、版本创建。
   - 支持 question、expected_answer、reference_contexts、reference_doc_ids、tags、metadata；question 必填，其余按所选指标决定可用性。
   - 暂定单文件不超过 50 MB、单版本不超过 10,000 条。

3. **离线评测任务**
   - 选择数据集版本、应用配置快照和指标配置后创建任务。
   - 通过标准评测对象契约逐样本获得回答、引用、检索上下文及工程数据。
   - 展示排队、运行、部分完成、完成、失败、取消状态和实时进度。
   - 失败样本可重试，但产生新的运行尝试，不覆盖原结果。

4. **内置指标**
   - 检索：参考文档召回率、MRR/首个相关文档排名、上下文覆盖率。
   - 生成：答案正确性、相关性、忠实性/幻觉风险。
   - 引用：引用存在率、引用覆盖率、引用支持度。
   - 工程：成功率、P50/P95 时延、Token、估算成本。
   - 缺少指标所需字段时显示“不可计算 + 原因”，不以 0 分替代。

5. **报告与样本下钻**
   - 总览、指标分布、标签切片、失败类型、样本列表和样本详情。
   - 样本详情并列展示问题、期望答案、实际答案、引用、检索上下文、指标解释和运行错误。
   - 支持按指标阈值、失败类型、标签、执行状态筛选。

6. **失败诊断**
   - 初始失败分类：检索遗漏、排序靠后、上下文不足、答案不忠实、答案不完整、引用缺失/不支持、目标应用错误、评测器错误、不可判定。
   - 每个诊断给出疑似阶段、证据、判断规则/评审器版本和置信度。
   - 用户可标记“准确 / 不准确”并填写备注。

7. **版本对比与发布门禁结论**
   - 选择一个基线运行和一个候选运行。
   - 校验数据集版本、样本集合和指标配置是否兼容。
   - 展示总体差值、标签切片差值、改善/回退/不变样本及新增错误。
   - 基于用户配置的关键指标阈值输出“通过 / 不通过 / 无法判断”；结论必须列出触发规则。

8. **最小权限与审计**
   - 项目级负责人、编辑者、只读者。
   - 记录数据集创建、配置变更、任务创建/取消和诊断反馈。

### 6.2 P1：MVP 验收后

- 生产 Trace 持续接入、在线抽样与告警。
- 自定义指标插件和自定义评审器。
- 数据集协作标注、冲突仲裁和主动学习采样。
- 多候选版本矩阵对比、显著性检验和趋势看板。
- 报告分享链接、PDF/演示文稿导出。
- 与 CI/CD 自动门禁集成。

### 6.3 明确不做

- 自动修改 Prompt、索引或模型配置并直接发布。
- 在线请求链路代理和生产流量控制。
- 模型微调、Embedding 训练或知识库内容生产。
- 多模态文档和多轮 Agent 轨迹评测。
- 用单一综合分数替代各阶段证据。
- 在 MVP 内承诺通用“根因确定性”；平台输出的是有证据的诊断建议。

## 7. 功能需求与验收标准

### FR-01 项目与应用配置快照

- **输入**：项目名称、负责人；评测目标；Prompt、模型、检索、Embedding、Rerank、知识库版本等配置字段。
- **操作**：创建项目；验证评测目标；保存新快照；查看快照差异。
- **输出**：项目、不可变配置快照 ID、连通性检查结果、掩码后的配置摘要。

**验收标准**

- 用户可在一个项目内创建多个具备唯一 ID 的应用配置快照。
- 任何已被运行引用的快照不可原地修改；编辑动作创建新快照。
- 访问凭据不出现在列表、报告、导出和审计详情中。
- 连通性检查区分认证失败、超时、契约不兼容和目标应用错误。
- 未提供的版本字段明确标为“未知”，不影响保存，但会出现在追溯完整性提示中。

### FR-02 数据集导入

- **输入**：CSV/JSONL 文件、字段映射、数据集名称与版本说明。
- **操作**：解析、预览、映射、校验、确认导入。
- **输出**：不可变数据集版本、字段覆盖统计、警告和逐行错误文件。

**验收标准**

- 系统拒绝缺少 question、无法解析、编码不支持或超过暂定容量上限的文件，并给出可行动的错误信息。
- 用户确认前能看到前 20 条映射后样本及字段覆盖率。
- 结构性错误存在时不创建半成品版本；修正后可重新校验。
- 仅缺少参考答案/参考文档时允许导入，但在指标选择时提示哪些指标不可计算。
- 相同文件重复导入时提示内容摘要一致；用户仍可用新版本说明确认创建。
- 成功版本记录文件摘要、样本数、字段映射、创建人和时间。

### FR-03 评测任务创建与执行

- **输入**：数据集版本、应用配置快照、指标配置、并发/超时的产品级限额。
- **操作**：预检、创建、执行、取消、重试失败样本。
- **输出**：任务与运行 ID、状态、进度、预计/实际消耗、逐样本结果。

**验收标准**

- 创建前展示数据集、应用和指标兼容性；阻断必需字段缺失的指标，并允许移除该指标后继续。
- 提交后 2 秒内返回任务 ID；页面刷新后状态和进度保持一致。
- 任务状态至少包含 queued、running、partially_completed、completed、failed、cancelled。
- 取消后不再发起新样本请求，已完成结果保留，并明确标记是否形成部分报告。
- 单样本失败不导致全部结果丢失；达到失败比例阈值后任务标为部分完成或失败，阈值可见。
- 重试只运行选定失败样本并生成新尝试记录，原始结果不可覆盖。

### FR-04 指标计算

- **输入**：样本参考字段、目标应用输出、检索上下文、指标配置。
- **操作**：计算规则指标和模型评审指标；记录解释。
- **输出**：样本级分数、聚合分数、可用性状态、评审证据。

**验收标准**

- 每个聚合值可下钻到参与计算的样本、分母和排除原因。
- 模型评审指标展示评审器、规则版本、评分理由和失败状态。
- 指标缺少输入、执行失败和真实 0 分是三个不同状态。
- 聚合报告默认同时展示样本数、有效样本数和置信区间/离散程度中至少一种。
- 成本估算同时展示计价版本和“估算”标识；没有价格依据时不计算。

### FR-05 报告与下钻

- **输入**：一个已完成或部分完成的运行。
- **操作**：查看总览、切片、筛选、排序并进入样本详情。
- **输出**：指标卡片、分布、失败构成、样本证据和可复制运行链接。

**验收标准**

- 报告头部始终显示数据集版本、应用配置快照、指标配置、运行时间和完成状态。
- 用户从任一聚合指标最多两次操作可到达对应失败样本列表。
- 标签多选、失败类型、分数范围和执行状态筛选可组合，且结果总数一致。
- 部分完成报告显著展示缺失样本数量，不把缺失样本计为 0 分。
- 样本详情保留原始文本换行，引用可定位到对应检索上下文。

### FR-06 失败诊断

- **输入**：样本指标、回答、引用、检索上下文、参考字段和运行错误。
- **操作**：生成诊断；按类型聚合；收集用户反馈。
- **输出**：疑似阶段、失败类型、证据、置信度/不可判定原因、反馈记录。

**验收标准**

- 每条非“不可判定”诊断至少包含一项可见证据和所用规则/评审器版本。
- 同一样本允许多个并列疑似原因，不强制压成单一根因。
- 检索信息缺失时不得输出“检索遗漏”确定结论，只能标记证据不足。
- 用户反馈提交后立即可见，记录操作者和时间，不改变历史原始诊断。
- 用户能从失败类型聚合进入对应样本，并返回原筛选上下文。

### FR-07 版本对比与门禁

- **输入**：基线运行、候选运行、关键指标阈值和最大回退样本比例。
- **操作**：兼容性检查、样本配对、计算差异、下钻回退样本。
- **输出**：总体/切片差值、改善/回退列表、门禁结论和触发规则。

**验收标准**

- 数据集版本或指标配置不一致时，默认不输出正式门禁结论；用户只能查看带警告的探索性对比。
- 正式对比的每个差值使用相同 sample_id 成对计算，并展示有效配对样本数。
- 对比分开展示 Prompt、模型、Embedding、Rerank、Top K 和知识库版本差异；未知项也需展示。
- 用户可一键筛选“基线通过但候选失败”的回退样本。
- 门禁结论可复算，且明确列出阈值、实际值、方向和未能计算的规则。
- 任一关键规则不可计算时，结果为“无法判断”，不得默认为通过。

### FR-08 权限与审计

- **输入**：项目成员和角色。
- **操作**：授权、撤权；查询审计记录。
- **输出**：生效权限和按时间排序的审计事件。

**验收标准**

- 只读者不能导入数据、创建/取消任务、修改配置或提交诊断反馈。
- 编辑者可操作评测资产但不能转移项目负责人。
- 所有变更类操作记录操作者、时间、对象、动作和结果；敏感值不入审计正文。
- 权限变更后，新请求立即按新权限判断；已打开页面的后续写操作必须重新校验。

## 8. 核心业务流程

### 8.1 数据集导入

项目 → 数据集 → 新建版本 → 上传文件 → 字段映射与预览 → 整批校验

- 有错误：下载错误明细并重新上传。
- 无错误：确认版本说明 → 生成不可变版本 → 进入创建评测任务。

### 8.2 评测任务

选择数据集版本 → 选择应用配置快照 → 选择指标配置 → 兼容性预检

- 预检通过：确认预计样本数与消耗 → 提交任务 → 查看进度。
- 完成/部分完成：打开报告。
- 失败：查看错误分布 → 选择失败样本重试。

### 8.3 报告查看

报告总览 → 选择指标或失败类型 → 标签/阈值筛选 → 样本列表 → 样本详情 → 查看回答、引用、检索上下文、评分理由与运行错误。

### 8.4 失败诊断

失败样本 → 阶段指标与证据对齐 → 输出一个或多个疑似原因 → 用户核对证据 → 标记准确性并备注 → 聚合诊断反馈供后续校准。

### 8.5 版本对比

选择基线运行 → 选择候选运行 → 兼容性检查 → 计算成对差值 → 查看总体与标签切片 → 下钻回退样本 → 检查门禁规则 → 得出发布建议。

## 9. 页面与流程草图说明

### 9.1 全局信息架构

- **项目列表**：项目名称、最近运行、健康摘要、负责人。
- **项目内导航**：总览 / 数据集 / 配置版本 / 评测任务 / 报告与对比 / 成员与审计。
- **全局上下文**：页面顶部固定项目；报告类页面固定展示运行与版本标识，避免用户误读跨版本数据。

### 9.2 关键页面

**数据集导入页**

- 左侧：步骤条（上传、映射、校验、确认）。
- 中间：样本表格预览和错误高亮。
- 右侧：字段覆盖率、可用指标、警告/错误统计。
- 底部：下载错误、返回修改、确认创建版本。

**任务创建页**

- 第一列：数据集版本与样本/标签摘要。
- 第二列：应用配置快照及与最近版本的差异。
- 第三列：指标勾选、所需字段和阈值。
- 提交区：预检结果、预计请求数/消耗、阻断项。

**报告页**

- 顶栏：运行状态和四类追溯信息。
- 第一屏：关键指标卡、分布、失败阶段漏斗、标签切片。
- 第二屏：可筛选样本表。
- 右侧抽屉：样本问题、答案、引用、检索上下文、指标理由和诊断。

**版本对比页**

- 顶栏：基线与候选选择器、兼容性状态。
- 中部：指标差值卡与切片差值。
- 下部：改善/回退/不变样本标签页。
- 侧栏：配置差异和门禁规则；结论固定展示触发证据。

## 10. 产品接口契约要求

以下为前后端、算法和目标应用之间必须一致的产品语义，不限定实现技术。

### 10.1 数据集样本契约

- 必有：sample_id、question。
- 可选：expected_answer、reference_contexts、reference_doc_ids、tags、metadata。
- sample_id 在数据集版本内唯一；版本创建后样本内容和 ID 不变。
- 文本、数组、对象类型需被显式校验，校验错误定位到行号和字段。

### 10.2 评测对象输出契约

- 必有：request_id、sample_id、answer、execution_status。
- 支持：citations、retrieved_contexts（含 doc_id、rank、content/摘要、score）、latency、token_usage、model_observation。
- 目标应用错误必须带稳定错误类别和可读摘要；密钥、完整凭据和敏感请求头不得进入结果。
- 如果目标应用无法提供某字段，平台保留“未提供”状态，并禁用依赖该字段的指标。

### 10.3 指标结果契约

- 每条结果包含 metric_id、metric_version、sample_id、status、score/value、reason、evidence_refs。
- status 至少区分 success、not_applicable、missing_input、evaluator_error。
- 聚合接口同时返回总样本数、有效样本数、排除数和排除原因分布。

### 10.4 任务与报告契约

- 任务状态变更有时间戳，状态查询和列表中的语义一致。
- 任务创建支持幂等标识，避免用户重复提交产生不可识别的重复运行。
- 报告只引用已固化运行结果；重试产生新尝试后，用户明确选择查看哪个尝试或合并视图。
- 所有列表支持稳定分页、排序和筛选条件回显。

## 11. 非功能需求

| 类别 | MVP 要求 |
| --- | --- |
| 性能 | 10,000 条报告的首屏在常规试点环境下 P95 不超过 3 秒；筛选/翻页 P95 不超过 2 秒；任务提交响应不超过 2 秒。 |
| 可靠性 | 已确认的数据集版本和已完成运行不得因单节点故障丢失；重复回调/提交不产生重复样本结果。 |
| 可复现 | 报告必须绑定数据集、应用配置、指标配置及评审器版本；历史运行不可被新配置重算覆盖。 |
| 安全 | 传输与存储中的敏感数据受保护；凭据采用引用方式；日志、报告和导出默认脱敏。 |
| 隔离 | 项目之间的数据、报告、凭据和审计不可越权访问。 |
| 可观测 | 任务级和样本级错误有稳定类别、关联 ID 与时间；运维可按关联 ID 排查且不暴露敏感正文。 |
| 可用性 | 错误信息说明原因与下一步；长任务可离开页面后继续；刷新不丢失进度。 |
| 可访问性 | 核心流程支持键盘操作；状态不只依赖颜色；表格和表单有可读标签。 |
| 兼容性 | MVP 支持当前两个主流桌面浏览器的最近两个稳定版本；CSV/JSONL 使用 UTF-8。 |
| 数据治理 | 支持项目级保留期配置入口或明确默认保留期；删除操作需二次确认并记录审计。 |

## 12. 发布与验收建议

MVP 以一个真实 RAG 应用、至少 500 条带业务标签的数据集进行端到端验收：

1. 导入包含合法、缺字段和格式错误样本的测试文件。
2. 运行一个基线和一个候选配置，覆盖成功、样本失败、取消与重试。
3. 验证检索、生成、引用、工程指标及不可计算状态。
4. 从指标卡下钻到失败样本，核对诊断证据。
5. 完成正式版本对比并触发一次通过、一次不通过、一次无法判断。
6. 用负责人、编辑者、只读者验证权限与审计。
7. 抽查历史报告，确认配置变化后结果和版本引用未改变。
