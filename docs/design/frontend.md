# RAGOps 前端信息架构与评测看板设计

> 状态：设计基线，尚未实现。本文定义 RAGOps 工程工作台的页面结构、交互、组件、数据字段与 API 依赖，供前后端联调和 MVP 排期使用。

## 1. 设计目标

RAGOps 前端服务于一条可追溯的评测与诊断链路：选择项目和版本，准备数据集，创建评测任务，定位失败样本，检查检索与生成证据，比较版本，最后观察质量、延迟和成本趋势。

设计原则：

- 第一屏是项目工作台，优先展示当前质量状态、进行中的任务和需要处理的问题。
- 任一聚合指标都能下钻到样本，任一样本都能追溯到任务、数据集快照、Prompt、模型、检索配置和引用文档。
- 筛选条件进入 URL，列表和图表之间保持联动，便于复现、分享和返回。
- 质量、性能、成本并列呈现，避免只优化单一分数。
- 明确区分“未运行”“无数据”“计算失败”和真实的零值。
- 桌面端优先，面向高信息密度的工程操作；窄屏保持可读，但不以移动端执行复杂诊断为目标。

## 2. 用户角色与核心任务

| 角色 | 核心任务 | 默认关注 |
| --- | --- | --- |
| RAG 应用工程师 | 创建评测、定位失败、比较配置 | 检索证据、生成答案、参数与日志 |
| 算法/Prompt 工程师 | 比较 Prompt、模型与检索版本 | 指标差异、回归/改善样本、置信区间 |
| 测试/质量负责人 | 维护数据集、审核失败、导出报告 | 覆盖率、失败类型、人工复核状态 |
| 项目负责人 | 判断发布风险、观察趋势与成本 | 质量门禁、版本趋势、延迟和费用 |

## 3. 信息架构

```text
/projects
└── /projects/:projectId
    ├── /overview                         项目概览
    ├── /datasets                         数据集管理
    │   └── /:datasetId                   数据集详情与版本
    ├── /evaluations                      评测任务列表
    │   ├── /new                          创建评测任务
    │   └── /:runId                       单次评测报告
    │       └── /samples/:sampleId        样本级诊断
    ├── /compare                          Prompt/模型/检索版本对比
    ├── /trends                           趋势看板
    └── /settings                         项目配置与质量门禁
```

### 3.1 全局框架

- 顶栏：项目切换、全局搜索、后台任务、帮助、用户菜单。
- 左侧导航：概览、数据集、评测任务、版本对比、趋势看板；项目设置固定在底部。
- 内容标题区：面包屑、页面标题、状态、主要操作、最后更新时间。
- 右侧检查器：按需展示筛选、任务配置、样本元数据或人工复核表单，不覆盖主要证据区。
- 全局反馈：任务提交成功后进入后台任务中心；长任务不使用阻塞式弹窗。

### 3.2 关键对象关系

```text
Project
├── Dataset ── DatasetVersion(snapshot)
├── PromptVersion
├── ModelVersion
├── RetrieverVersion
└── EvaluationRun
    ├── EvaluationConfig（引用上述不可变版本）
    ├── MetricSummary
    └── EvaluationSampleResult
        ├── RetrievedDocument / ContextChunk
        ├── GeneratedAnswer / Citation
        ├── MetricScore
        └── FailureLabel / HumanReview
```

评测任务必须引用不可变的数据集和配置版本。若后端仅提供可变对象，前端需要展示快照 ID 与创建时间，并阻止把旧报告误标为当前版本结果。

## 4. 核心工作流

### 4.1 首次基线评测

1. 在数据集管理中导入样本并完成字段映射。
2. 发布数据集版本，冻结样本数量与内容哈希。
3. 从评测任务页选择数据集快照、被测配置和指标集合。
4. 预检通过后启动任务，在列表中查看进度与失败原因。
5. 进入单次报告，查看质量门禁、指标分布和失败类型。
6. 从图表或失败列表下钻到样本级诊断，记录故障归因和复核结论。

### 4.2 回归比较

1. 从单次报告选择“设为基线”或“与其他版本比较”。
2. 在版本对比页锁定同一数据集快照和指标定义。
3. 查看总体差异、置信区间、回归/改善样本集合。
4. 下钻到配对样本，检查检索文档、上下文、答案和引用变化。
5. 导出比较报告，或复制当前筛选链接供评审。

### 4.3 故障诊断

1. 从失败类型、低分分桶或查询搜索进入样本。
2. 按“输入 → 检索 → 上下文 → 生成 → 评分”顺序阅读证据。
3. 高亮答案引用与上下文片段的对应关系，识别缺失、错误或无支持引用。
4. 标记主要故障类型、备注和审核状态。
5. 使用“上一条/下一条”保留原筛选队列连续审核。

## 5. 页面规格

### 5.1 项目概览 `/projects/:projectId/overview`

目标：在一屏内回答“当前版本是否可发布、最近发生了什么、下一步要处理什么”。

页面模块：

- 当前发布候选：Prompt、模型、检索器和数据集快照版本，支持跳转到版本对比。
- 核心指标卡：答案正确性、忠实度、检索召回、引用完整性、通过率；显示当前值、与基线差异、阈值状态、样本数。
- 质量门禁：逐条显示规则、观测值、阈值、通过/告警/失败状态。
- 最近评测任务：运行状态、进度、触发人、开始时间、配置摘要。
- 失败类型分布：点击某一类型进入对应报告并自动带入筛选。
- 质量/延迟/成本迷你趋势：共享时间范围，异常点可跳转到对应任务。
- 待处理事项：运行失败、数据集校验错误、未审核的 P0/P1 失败样本。

主要操作：“新建评测”“比较版本”“导入数据集”。

### 5.2 数据集管理 `/projects/:projectId/datasets`

目标：管理可复现的评测输入，清楚区分草稿与已发布快照。

列表字段：名称、当前版本、状态、样本数、语言/领域标签、必填字段覆盖率、最近评测时间、创建人、更新时间。

关键交互：

- 支持 JSONL/CSV 上传；上传后先进入预检，不立即发布。
- 字段映射至少覆盖 `query`，可选 `reference_answer`、`relevant_document_ids`、`metadata`、`tags`。
- 预检展示解析错误、重复 ID、空问题、引用文档缺失、超长内容及其样本定位。
- 发布动作生成不可变 `dataset_version_id`；内容变化必须创建新版本。
- 数据集详情支持样本表格、字段筛选、版本差异、抽样预览和导出。
- 被评测任务引用的版本不可删除；归档操作必须说明影响范围。

### 5.3 评测任务列表 `/projects/:projectId/evaluations`

目标：创建、监控和检索评测运行。

列表字段：任务名/ID、状态、配置版本摘要、数据集版本、进度、通过率、主要指标、失败样本数、P95 延迟、估算/实际成本、触发方式、开始时间、耗时、创建人。

筛选：状态、时间、数据集版本、Prompt/模型/检索版本、标签、质量门禁结果、创建人。筛选写入 URL 查询参数。

关键交互：

- 创建任务使用三步抽屉：选择数据与配置 → 选择指标和采样 → 预检与确认。
- 预检包含版本完整性、样本量、评测器可用性、预算估算和预计耗时。
- 运行中支持查看实时进度；仅在后端支持幂等取消时显示“取消”。
- 失败任务展示失败阶段、错误摘要、重试资格和关联日志 ID。
- 批量导出仅针对已完成任务；导出操作必须记录筛选范围和生成时间。

### 5.4 单次评测报告 `/projects/:projectId/evaluations/:runId`

目标：判断任务质量，并把聚合异常快速缩小到可解释的样本集合。

页面模块：

- 固定配置头：任务状态、数据集快照、Prompt/模型/检索器、指标定义版本、提交哈希、开始/结束时间。
- 质量门禁结论：通过/告警/失败；门禁未配置时展示“未配置”，不能显示为通过。
- 指标卡：分数、阈值、基线差、样本数、缺失数、置信区间。
- 指标分布：直方图/分桶条形图；刷选分数区间联动样本表。
- 失败类型分布：水平条形图，显示数量与占比；支持多选叠加筛选。
- 检索表现：Hit@K/Recall@K/MRR、首个相关文档排名、无命中占比。
- 延迟/成本：端到端及各阶段 P50/P95/P99、Token 与成本分解。
- 样本结果表：支持保存视图、列配置、排序、服务端分页和导出。

默认样本列：样本 ID、查询摘要、总结果、关键指标、失败类型、检索命中、引用状态、延迟、成本、人工审核状态。

下钻规则：指标卡、分布图、失败类型、异常点和样本表共享一套筛选模型；点击任一图形后，页面滚动到样本区并显示可移除的筛选标签。

### 5.5 样本级诊断 `/projects/:projectId/evaluations/:runId/samples/:sampleId`

目标：基于完整证据链定位检索、上下文、生成或评分故障。

页面布局：

- 顶部：样本位置、上一条/下一条、总结果、故障标签、审核状态、复制链接。
- 输入与期望：用户查询、参考答案、期望文档、标签与业务元数据。
- 检索证据：按排名展示文档/片段、分数、文档 ID、版本、字符区间、相关性标记。
- 上下文装配：显示实际传入模型的片段顺序、截断位置、Token 数和重复片段。
- 答案与引用对照：答案中的引用标记与来源片段双向高亮；同时展示参考答案差异。
- 指标解释：各指标得分、阈值、评测器、理由、原始响应引用和计算状态。
- 运行遥测：检索/重排/生成/评测阶段耗时、Token、成本、trace/log ID。
- 人工复核：主要故障类型、次要标签、严重级别、结论、备注、审核人和时间。

推荐故障分类：

| 阶段 | 类型示例 |
| --- | --- |
| 数据 | 问题无效、参考答案错误、期望文档缺失 |
| 检索 | 无命中、相关文档排名低、查询改写偏移、过滤错误 |
| 上下文 | 关键片段截断、顺序不佳、冗余/冲突、预算不足 |
| 生成 | 幻觉、拒答错误、答案不完整、格式不合规 |
| 引用 | 缺少引用、引用错配、引用不支持结论、粒度过粗 |
| 评测 | 评测器失败、指标不适用、自动评分与人工判断冲突 |

### 5.6 版本对比 `/projects/:projectId/compare`

目标：在可比条件下识别新版本的收益、回归和代价。

前置校验：默认要求同一数据集快照、样本集合和指标定义；不满足时显示不可比原因。允许继续探索时，必须显著标注“非严格对比”，并仅计算交集样本。

页面模块：

- 对比选择器：基线运行 A、候选运行 B，可增加 C/D 做探索；发布决策默认使用 A/B 配对比较。
- 配置差异：Prompt、模型、检索、重排、上下文预算、温度及提交哈希逐项 diff。
- 指标差异表：A/B 值、绝对差、相对差、置信区间、改善/持平/回归样本数。
- 配对散点图：横轴基线、纵轴候选；象限点击筛选回归或改善样本。
- 失败类型迁移：展示失败类型新增、消失和迁移，不仅比较总量。
- 延迟/成本权衡：质量增益对 P95 延迟和单位样本成本增量。
- 配对样本表：同一行显示 A/B 答案摘要、关键指标、故障类型和差值。

### 5.7 趋势看板 `/projects/:projectId/trends`

目标：监控质量、性能和成本的长期变化，并追溯异常点。

全局筛选：时间范围、环境、数据集系列、Prompt/模型/检索版本、标签、触发方式。图表必须明确聚合粒度与样本量。

页面模块：

- 质量趋势：通过率与核心指标；阈值线、版本发布标记、置信区间。
- 检索趋势：Recall@K、MRR、无命中率。
- 失败类型堆叠：数量/占比切换，避免样本量变化造成误读。
- 延迟趋势：P50/P95/P99，按检索、重排、生成、评测分解。
- 成本趋势：总成本、单样本成本、按模型/阶段分解，显示币种和计价版本。
- 运行稳定性：成功率、取消率、评测器错误率、数据缺失率。
- 版本事件轴：版本切换、数据集发布、门禁阈值变更。

点击任意趋势点打开对应运行列表；聚合点包含多个运行时，先展示运行选择浮层，不直接跳到任意一条。

## 6. 可视化与字段契约

### 6.1 通用字段

每个指标或时间序列点至少包含：

```ts
type MetricPoint = {
  metric_key: string;
  metric_name: string;
  value: number | null;
  unit: "score" | "ratio" | "ms" | "tokens" | "currency" | "count";
  sample_count: number;
  missing_count: number;
  threshold?: { operator: ">=" | "<="; value: number };
  baseline_value?: number | null;
  delta?: number | null;
  confidence_interval?: { lower: number; upper: number; level: number };
  status: "pass" | "warning" | "fail" | "not_configured" | "unavailable";
  computed_at: string;
  definition_version: string;
};
```

显示规则：空值使用 `—` 并附原因；比率显示分子/分母；成本显示币种；延迟显示聚合口径；自动评分要展示评测器和定义版本。

### 6.2 图表字段

| 可视化 | 必需维度 | 必需指标 | 交互 |
| --- | --- | --- | --- |
| 指标卡 | `metric_key` | 值、阈值、基线差、样本/缺失数、置信区间 | 点击按指标下钻 |
| 失败类型分布 | `failure_type`、`severity` | 数量、占比、已审核数 | 多选筛选样本 |
| 指标分布 | 分数分桶 | 数量、累计占比 | 刷选区间 |
| 检索排名 | `rank`、`relevance` | 检索分数、是否期望文档 | 展开片段、定位文档 |
| 引用对照 | `citation_id`、答案区间、片段区间 | 支持状态、匹配置信度 | 双向高亮 |
| 版本配对散点 | `sample_id` | A 分数、B 分数、差值 | 象限筛选、打开样本 |
| 质量趋势 | 时间桶、版本 | 指标均值/通过率、样本数、置信区间 | 缩放、点击运行 |
| 延迟趋势 | 时间桶、阶段 | P50/P95/P99、样本数 | 阶段显隐、点击异常 |
| 成本趋势 | 时间桶、模型/阶段 | 总成本、单样本成本、Token | 币种提示、分解 |

### 6.3 颜色与语义

- 状态色只表达语义：通过为绿、告警为黄、失败为红、运行中为蓝、未知/未配置为灰。
- 版本系列使用色盲友好的离散色，不复用状态色表达版本优劣。
- 所有图表同时使用文字、形状或线型传达状态，不能只依赖颜色。
- 回归差异统一以“候选 B - 基线 A”计算；界面固定显示差值方向。

## 8. URL 与状态管理

可分享的筛选状态放在 URL 查询参数中，例如：

```text
/projects/p1/evaluations/r42?metric=faithfulness&score_max=0.5&failure_type=unsupported_claim&review=unreviewed&sort=score:asc
```

- URL 保存筛选、排序、分页、时间范围、基线/候选运行 ID 和可见标签页。
- 抽屉开关、悬停状态、临时列宽留在本地状态。
- 保存视图仅保存查询定义，不保存结果快照；重新打开时显示数据更新时间。
- 返回列表时恢复滚动位置和筛选；样本上一条/下一条基于进入时的服务端结果集合。

## 9. API 依赖

以下为前端所需的能力与建议资源，不代表仓库中已存在这些接口。具体路径可由后端调整，但响应语义应保持。

| 页面/能力 | 建议接口 | 关键响应字段 |
| --- | --- | --- |
| 项目框架 | `GET /api/projects/:id` | 项目、权限、时区、币种、默认门禁 |
| 项目概览 | `GET /api/projects/:id/overview` | 当前版本、指标摘要、门禁、最近运行、待办 |
| 数据集列表 | `GET /api/projects/:id/datasets` | 分页、版本、样本数、状态、校验摘要 |
| 数据集导入 | `POST /api/datasets/:id/imports` | 上传会话、字段映射、解析进度 |
| 数据集校验 | `GET /api/dataset-imports/:id/validation` | 错误类型、数量、样本定位 |
| 发布版本 | `POST /api/datasets/:id/versions` | 不可变版本 ID、哈希、样本数 |
| 评测列表 | `GET /api/projects/:id/evaluation-runs` | 服务端筛选/排序/分页、摘要指标 |
| 任务预检 | `POST /api/evaluation-runs/preflight` | 可用性、样本量、预算、预计耗时、阻塞项 |
| 创建任务 | `POST /api/evaluation-runs` | 运行 ID、快照配置、初始状态 |
| 任务进度 | `GET /api/evaluation-runs/:id/progress` 或 SSE | 阶段、已处理/总数、失败数、心跳时间 |
| 单次报告 | `GET /api/evaluation-runs/:id/report` | 配置快照、门禁、指标/失败/延迟/成本聚合 |
| 样本列表 | `GET /api/evaluation-runs/:id/samples` | 服务端筛选、排序、游标、摘要字段 |
| 样本诊断 | `GET /api/evaluation-runs/:id/samples/:sampleId` | 输入、检索、上下文、答案、引用、评分、遥测 |
| 人工复核 | `PUT /api/evaluation-runs/:id/samples/:sampleId/review` | 乐观锁版本、审核结果、审核人、时间 |
| 版本对比 | `POST /api/evaluation-comparisons` | 可比性、配置 diff、配对指标、迁移统计 |
| 趋势查询 | `GET /api/projects/:id/trends` | 时间桶、系列、版本事件、样本/缺失数 |
| 导出 | `POST /api/exports`、`GET /api/exports/:id` | 导出范围、状态、过期下载地址 |

### 9.1 API 通用要求

- 列表采用稳定排序和游标分页；返回 `total` 时需注明是否精确。
- 聚合接口返回实际应用的筛选条件、时区、聚合粒度和数据更新时间。
- 所有运行、版本、样本和文档使用稳定 ID；展示名不能充当关联键。
- 长任务返回可查询的任务 ID，并支持幂等创建键；取消、重试和发布等写操作需要明确权限。
- 错误响应至少包含 `code`、`message`、`request_id`、可选字段级 `details`。
- 报告响应需要区分 `pending`、`failed`、`not_applicable` 和数值结果。
- 样本复核写入需要版本号或 ETag，冲突时提示刷新，避免覆盖他人审核。
- Token/成本同时返回原始用量、单价版本、币种和计算时间。

## 10. 非功能要求

- 性能：概览首屏骨架立即出现；聚合请求与列表请求分离；10 万级样本使用服务端分页，禁止一次加载全量。
- 可访问性：键盘可达、明显焦点、图表数据表替代、对比度达标、状态非纯色表达。
- 可观测性：前端错误携带 `request_id`；关键操作记录 project/run/sample ID，禁止记录完整问题、答案和文档正文。
- 安全：按项目权限控制导出、查看原文、启动/取消任务和人工审核；敏感内容支持遮蔽。
- 国际化：时间按项目时区展示并可查看 UTC；数值与币种格式化；指标 key 与展示名分离。
- 数据新鲜度：轮询/SSE 中断时显示“数据可能已过期”，保留最后成功更新时间。

## 11. MVP 优先级

| 优先级 | 页面/能力 | 范围 | 完成判断 |
| --- | --- | --- | --- |
| P0 | 全局框架与项目概览 | 项目导航、指标卡、门禁、最近任务、待办 | 能判断当前质量状态并进入任务 |
| P0 | 评测任务列表与创建 | 筛选、进度、预检、创建、失败说明 | 能启动并追踪一次可复现评测 |
| P0 | 单次评测报告 | 配置快照、指标/失败分布、样本表、延迟成本 | 聚合指标可下钻到筛选后的样本 |
| P0 | 样本级诊断 | 检索、上下文、答案引用、指标解释、人工复核 | 能完成一次有证据的故障归因 |
| P1 | 数据集管理 | 导入、映射、校验、发布快照、样本预览 | 能构建并冻结评测数据集版本 |
| P1 | 双版本对比 | 可比性检查、配置 diff、指标差、回归样本 | 能做 A/B 配对回归判断 |
| P2 | 趋势看板 | 质量、失败、延迟、成本、版本事件 | 能跨运行观察异常并追溯 |
| P2 | 保存视图与异步导出 | 视图复用、导出任务中心 | 可分享和沉淀分析结果 |

建议实施顺序为：框架与只读报告 → 样本诊断 → 任务创建/进度 → 数据集导入发布 → 版本对比 → 趋势与导出。若后端任务 API 先成熟，可将任务创建与只读报告并行推进。

## 12. 前后端联调验收场景

1. 用户从失败类型图点击“引用错配”，样本表同步筛选，刷新和复制链接后条件保持。
2. 用户从样本诊断连续查看下一条，筛选集合不丢失，返回报告后回到原位置。
3. 两次运行的数据集快照不同，对比页阻止严格比较并解释差异；选择交集探索时显著标注。
4. 指标尚未计算、评测器失败和真实分数 0 分别显示，不相互混淆。
5. 一个运行中的任务断开实时连接后，页面显示最后更新时间和过期提示，恢复连接后补齐进度。
6. 人工复核发生版本冲突时，不覆盖他人结果，并能展示服务器上的新版本。
7. 成本图能追溯到模型、Token 用量、币种和计价版本；未知成本不按 0 统计。
8. 任一聚合图表的导出或下钻都携带相同筛选口径、样本数和时间范围。
